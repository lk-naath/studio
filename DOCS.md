# Documentation Standard

Write documentation that is clear, factual, useful, and easy to maintain.

## Write

- Give each document one clear subject, title, and meaningful section structure.
- State facts directly and separate confirmed information from assumptions or open questions.
- Mark unknowns as `Not documented yet`; never invent missing names, dates, numbers, claims, or capabilities.
- Use exact dates in `YYYY-MM-DD` format when the day is known.
- Keep terminology consistent and update the existing source when facts change.

## Keep separate

- Knowledge files contain facts, definitions, decisions, and instructions.
- Stories, hooks, opinions, and promotional narratives belong in generated deliverables, not source knowledge.
- Generated content must remain traceable to the available facts.

## Avoid

- Duplicate facts, unrelated topics, filler, vague wording, and long background sections.
- Presenting assumptions or plans as completed facts.
- Using diagrams or tables unless they clarify a relationship or comparison.

Use lowercase directory names and uppercase descriptive Markdown filenames such as `ABOUT.md` or `POST.md`.
